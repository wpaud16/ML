# 임차인 자료 (사용자 PC → 저장소)

사용자 PC(LAPTOP-M47J0JTR)가 매일 **05:30 KST**에 법원경매정보(courtauction.go.kr) 매각물건명세서·임차인 현황을 읽어
`auction_model/tenants/latest.json` 으로 올린다. 06:10 예측 작업(`batch_predict.py` → `tenant_rules.py`)이 이 파일로
"낙찰금으로 보증금이 다 변제되는지"를 계산해 숨김/포함을 다시 판정한다. 파일이 없거나 14일 넘게 오래되면 리치고 판정 그대로.

조회 대상: `auction_model/predictions/tenant_targets.json` (전날 예측 물건 목록: key, case, item_no, court, bidding_date, category)

## latest.json 형식

```json
{
  "generated_at": "2026-11-04T05:31:00+09:00",
  "items": {
    "2026타경101140[1]": {
      "checked": "2026-11-04",                 // 조회한 날 (YYYY-MM-DD)
      "court": "서울중앙지방법원",
      "base_right_date": "2024-05-16",         // 말소기준권리 접수일 (명세서 '최선순위 설정일자')
      "base_right": "가압류",
      "dividend_deadline": "2026-03-10",       // 배당요구종기
      "tenants": [
        {
          "occupant": "임차인",                 // 점유자 구분 (임차인/소유자/채무자 등)
          "move_in": "2023-02-01",             // 전입신고일 (사업자등록일)
          "fixed_date": "2023-02-01",          // 확정일자 (없으면 null)
          "deposit_manwon": 15000,             // 보증금 (만원)
          "monthly_rent_manwon": 0,            // 차임 (만원)
          "claimed_dividend": true,            // 배당요구 여부
          "claim_date": "2026-01-05"           // 배당요구일 (모르면 null)
        }
      ],
      "remarks": "매각물건명세서 비고란 원문",
      "assumed_rights_text": "등기된 부동산에 관한 권리 또는 가처분으로 매각으로 효력이 소멸되지 아니하는 것 (원문)",

```
날짜는 모두 YYYY-MM-DD, 금액은 만원 정수. 임차인이 없으면 `"tenants": []`.

## 추가 필드 (2026-11-03~)
물건마다 위 필드에 더해 아래를 함께 기록한다.
```json
{
  "bidding_date": "2026-11-17",               // 조회 기준 매각기일 (대상 목록 값, 없으면 기일내역의 다음 매각기일)
  "category": "오피스텔",                      // 대상 목록의 category (아파트/오피스텔)
  "occupancy": {                               // 현황조사서 (이 물건의 소재지 부분만)
    "occupant_type": "임차인(별지)점유",        // 점유관계 (미상 / 채무자(소유자)점유 / 임차인(별지)점유 등)
    "lessee_count": 1,                         // 부동산임대차정보의 임대차관계 인원
    "periods": [                               // 임대차관계 조사서의 점유인별 내용 (이름 제외)
      {"occupant": "임차인", "use": "주거", "period": "미상", "move_in": "2023-03-31"}
    ],
    "surveyed": ["2026-03-24", "2026-03-26"],  // 조사일
    "text": "1) 이 사건 부동산의 전입세대확인서에는 ...",  // '기타' 조사 내용 원문 (앞 600자)
    "closed_absent": true                      // 폐문·부재(점유자를 만나지 못함) 여부
  },
  "events": [                                  // 문건처리·송달 내역 최근 20건 (최신순, 원문)
    {"date": "2026-06-22", "type": "배당요구", "text": "가압류권자 서OOOOOOO 권리신고및배당요구신청 제출"},
    {"date": "2026-06-09", "type": "송달", "text": "임차권자 이OO 최고서 발송 → 2026.06.10 송달간주"}
  ],
  "schedule": [                                // 기일내역 (물건상세)
    {"date": "2026-10-13", "kind": "매각기일", "result": "유찰", "min_price_manwon": 24500},
    {"date": "2026-11-17", "kind": "매각기일", "result": null, "min_price_manwon": 19600}
  ],
  "warnings": ["현황조사서 실패: ..."]          // (있을 때만) 명세서 외 부분 조회 실패 — error와 달리 판정에는 영향 없음
}
```
- `events[].type`: 문건은 내용에 따라 `배당요구` / `권리신고` / `유치권신고` / `취하` / `연기신청` / `변경신청` / `정지` / `개시결정`, 해당 없으면 `문건`. 송달은 결과가 불능·폐문·부재·불명이면 `송달불능`, 아니면 `송달`.
- 법원경매정보는 **매각물건명세서를 매각기일 1주 전부터만** 공개한다. 그 전에는 `error`가 `"매각물건명세서 공개 전 ..."`이고 명세서 필드(base_right·tenants 등)는 비어 있다 (occupancy·events·schedule은 채움). 이런 물건은 기일 1주 전이 되면 다시 조회한다.
- 다시 조회하지 않는 경우: 3일 안에 조회했고 매각기일이 같고 `error`가 없는 물건 → 이전 값 유지. 05:30에 시작해 35분이 넘으면 남은 물건도 이전 값 유지 (매각기일 빠른 순으로 조회).
- 명세서 표에서 같은 임차인이 여러 줄(임차권등기·권리신고 승계인·현황조사)로 나오면 전입일이 같고 보증금이 같거나 한쪽이 미상일 때 한 명으로 합친다. 배당요구 칸이 비어 있어도 비고에 배당요구일(또는 "신청채권자"로 보증금반환채권 승계)이 적혀 있으면 `claimed_dividend: true`로 본다.
- 보증금이 `미상`이면 `deposit_manwon: null`.
- 저장소가 공개라서 `remarks`·`assumed_rights_text`·`occupancy.text`의 개인 이름은 법원 사이트처럼 `이OO` 꼴로 가린다.
